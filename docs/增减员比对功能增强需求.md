# 增减员比对功能增强需求

## 概述

当前增减员比对功能基于"个税端导出文件 + 发薪月份"进行全员比对。本次增强旨在：
1. 支持按经办人/结算单元过滤，实现业务员自助查看
2. 完善减员规则，避免误减"已做工资单但未发薪"人员
3. 支持多维度筛选（发薪月份、未发薪工资表所属月份、合同签署时间）
4. 特殊结算单元的工资为0人员过滤

---

## 需求清单

### 需求 1：按经办人/结算单元过滤

**业务场景**：多个业务员分别管理不同结算单元的人员，需要各自查看自己负责的增减员数据。

**功能要求**：
- 全员比对完成后，提供筛选条件：经办人、结算单元
- 每个业务员只能看到自己负责的增减员数据
- 筛选条件可多选

**数据流**：
```
全员比对 → 应用筛选条件 → 输出过滤后的增减员数据
```

---

### 需求 2：减员规则完善

**当前问题**：部分人员已做工资单但未发工资，被误判为减员。

**新规则**：
- **可减员条件**（必须同时满足）：
  1. TC93 表中没有该人员的工资记录
  2. TC8M 表中没有该人员当月发的工资记录
  
- **不可减员条件**（任一满足即保留）：
  1. 有未发薪的工资表（TC93 有记录但 TC8M 未发）
  2. 个税端在册且未离职

**判断逻辑**：
```
if (TC93有记录 AND TC8M未发) OR (个税端在册 AND 未离职):
    保留不减员
else:
    列入减员名单
```

---

### 需求 3：发薪月份筛选逻辑

**当前实现**：支持选择 1-2 个发薪月份。

**新规则**：
- 只保留一个发薪月份选择框
- 选中月份 → 自动扩展到"选中月份至最近一个发薪月份"的范围

**示例**：
- 选中 2026年6月 → 查询 6月、7月 的发薪人员名单（假设7月是最近发薪月份）
- 选中 2026年7月 → 只查询 7月 的发薪人员名单

**用途**：用于判断"增员"条件 ①（当月有发薪）

---

### 需求 4：未发薪工资表所属月份筛选

**新增功能**：新增"未发薪工资表所属月份"选择框。

**规则**：
- 选中月份 → 自动扩展到"选中月份至当前月"的范围
- 查询该范围内 TC93 有记录但 TC8M 未发的人员

**示例**：
- 选中 2026年6月 → 查询 6月、7月所属月份的未发薪工资表人员
- 选中 2026年7月 → 只查询 7月所属月份的未发薪工资表人员

**用途**：用于判断"增员"条件 ②（当月有未发薪的工资表）和"减员"排除条件

---

### 需求 5：合同签署时间筛选

**新增功能**：新增"合同签署时间"选择框。

**规则**：
- 选中月份 → 筛选合同开始日期在"选中月份当月1日"至"当前上报发薪月份最后一天"之间的人员
- 这些人员即使没有工资表，也需要增员

**示例**：
- 选中 2026年7月，当前上报月份为 7月 → 合同开始日期在 7月1日 至 7月31日 之间
- 这些人员即使没有工资表，也需要增员

**用途**：用于判断"增员"条件 ③（合同开始日期属于当月但未作工资表）

---

### 需求 6：增员条件汇总

**增员判断逻辑**（满足任一即增员）：

| 条件 | 说明 | 数据来源 |
|------|------|----------|
| ① 当月有发薪 | 发薪月份筛选范围内有发薪记录 | TC8M 已发 |
| ② 当月有未发薪工资表 | 所属月份筛选范围内有未发薪记录 | TC93 有记录 + TC8M 未发 |
| ③ 合同开始日期属于当月 | 合同签署时间筛选范围内，但未作工资表 | TC90.ATC90C |

**前提条件**：员工不在个税端人员表中（不在职）

---

### 需求 7：特殊结算单元过滤

**业务场景**：某些结算单元（如二院）当月发薪多批次，合计工资为0，不应增员。

**功能要求**：
- 用户可配置"工资为0不增员"的结算单元列表
- 配置方式：界面输入结算单元代码/名称，或从数据库选择
- 过滤逻辑：选中结算单元的人员，当月发薪合计工资为0时，不列入增员名单

**配置存储**：
- 建议存储在数据库表或配置文件中
- 支持增删改查

## 技术要点

### 1. 发薪月份范围计算
```python
def get_pay_month_range(selected_month):
    """
    选中月份 → 至最近发薪月份的范围
    例：选中202606，最近发薪202607 → [202606, 202607]
    """
    latest_month = get_latest_pay_month()  # 从TC8M查询
    if selected_month >= latest_month:
        return [selected_month]
    else:
        return list(range(selected_month, latest_month + 1))
```

### 2. 未发薪人员查询
```sql
-- TC93有记录但TC8M未发的人员
SELECT DISTINCT t93.AAC001
FROM TC93 t93
LEFT JOIN TC8M m ON m.ATB930 = t93.ATB930 
                AND m.ATC931 = t93.ATC931 
                AND m.ATC937 = t93.ATC937
                AND m.ATC8M3 = 2  -- 已发
WHERE t93.ATC931 IN (:salary_months)  -- 所属月份范围
  AND m.ATB930 IS NULL  -- TC8M未发
```

### 3. 合同签署时间筛选
```sql
-- 合同开始日期在指定范围内的人员
SELECT DISTINCT AAC002
FROM TC90
WHERE ATC90C BETWEEN :start_date AND :end_date
```

### 4. 特殊结算单元过滤
```sql
-- 查询结算单元当月合计工资
SELECT ATB930, SUM(ATC93AA) as total_salary
FROM TC93
WHERE ATC931 = :pay_month
GROUP BY ATB930
HAVING SUM(ATC93AA) = 0
```

## 待确认事项（已确认）

1. **经办人数据来源**：
   - 发薪人员：TC8M.AAE019（经办人）
   - 未发薪工资表：TC93 相关字段（需确认字段名，可能是 AAE019 或类似）
   - 签合同未做工资单：TC90 相关字段（需确认字段名）

2. **结算单元数据来源**：
   - 发薪人员：TC8M.ATB930（结算单元代码）+ 名称映射
   - 未发薪工资表：TC93.ATB930 + 名称映射
   - 签合同未做工资单：TC90 相关字段（需确认字段名）

3. **特殊结算单元配置**：需要界面配置（增删改查）

4. **"最近一个发薪月份"**：TC8M 中最新的 ATC8G7（已发状态 ATC8M3=2）

5. **"当前上报发薪月份"默认值逻辑**：
   - 用户手动选择发薪月份
   - **默认值规则**：
     - 系统时间 1日-15日 → 默认选**上个月**
     - 系统时间 16日-月末 → 默认选**本月**（如果有）
   - **业务原因**：报税一般在发薪月过完后半个月内完成
   - **示例**：
     - 今天是 2026-09-10（1-15日）→ 默认选 2026年8月
     - 今天是 2026-09-20（16-月末）→ 默认选 2026年9月（如果已有发薪记录）
