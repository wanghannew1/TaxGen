# TC8M 与 TC93 关系说明

## 表职责

| 表 | 用途 | 粒度 |
|---|---|---|
| TC8M | 工资发放批次汇总 | 每条记录 = 一个结算单元 + 所属月份 + 批次 + 发放银行 |
| TC93 | 工资明细 | 每条记录 = 一个人的工资明细 |

## 关联字段

TC8M 和 TC93 通过以下字段关联：

| 字段 | 含义 | 说明 |
|---|---|---|
| ATB930 | 结算单元流水号 | 两边一致 |
| ATC931 | 工资所属年月 | 格式 YYYYMM |
| ATC937 | 工资发放次数（批次号） | 同一结算单元同一月可有多次发放 |
| BBB002 | 发放银行 | 同一结算单元同一月同一批次可能按银行拆分 |

## BBB002（发放银行）导致的记录拆分

**同一结算单元 + 同一所属月份 + 同一批次，TC8M 和 TC93 都可能因发放银行不同而产生多条记录。**

示例：吉林大学继续教育学院 202607 第1批次

| 表 | BBB002 | 人数 | 金额 |
|---|---|---|---|
| TC8M | 04000 | 29 | 108,223.29 |
| TC8M | 02000 | 19 | 85,288.03 |
| **TC8M合并** | — | **48** | **193,511.32** |
| TC93 | 04 | 29 | — |
| TC93 | 02000 | 19 | — |
| **TC93合计** | — | **48** | **193,511.32** |

**结论：两边人数和金额完全一致。**

## 金额字段对应关系

TC8M 的"发放总额"对应 TC93 的**实发金额（ATC93C）**，不是工资总额（ATC93AA）。

| TC8M字段 | 含义 | 对应TC93字段 |
|---|---|---|
| ATC8M1 | 发放人数 | COUNT(*) |
| ATC8M2 | 发放总额 | ATC93C（实发金额）|

同一条记录中：
- ATC93AA（工资总额）= 240,885.19
- ATC93C（实发金额）= 193,511.32 ← 与 TC8M.ATC8M2 一致

## 查询流程

### 建议批次查询（get_suggestions）

```
TC8M WHERE ATC8G7 = 发放月份 AND ATC8M3 = 2
GROUP BY ATB930, ATB931, ATC931, ATC937  -- 按银行合并
```

- ATC8G7 = 经办年月（即用户选择的发放月份）
- ATC8M3 = 2 表示已确认发放
- GROUP BY 自动合并不同银行的记录，SUM 人数和收入

### 工资记录查询（get_salary_records）

```
TC93 LEFT JOIN AC01
WHERE ATC931 = 所属月份
```

- 用 ATC931（所属月份）过滤，不涉及 ATC937
- 生成 Excel 时，通过 confirmed_combos 进一步过滤：ATB930 + ATC931 + ATC937

### 确认组合过滤

用户在 UI 中勾选的组合，作为 confirmed_combos 传给后端：

```python
# app.py 中的过滤逻辑
combo_set = {(c["unit"], c["salary_month"], c["seq"]) for c in confirmed_combos}
records = [r for r in records if (r.结算单元, r.工资所属年月, r.当月批次) in combo_set]
```

过滤条件使用 ATB930 + ATC931 + ATC937，**不涉及 BBB002（银行）**，所以合并后的 TC8M 组合能正确匹配到 TC93 的所有记录（无论银行）。

## 关键约束

1. **报税不关心发放银行**：TC8M 按银行拆分是银行业务需要，个税报送以结算单元+月份+批次为维度
2. **生成时不依赖 TC8M**：TC93 自身包含完整的工资明细，TC8M 仅用于确定"哪些组合需要报税"
3. **人数和金额必须对得上**：TC8M 的 ATC8M1（人数）和 ATC8M2（总额）必须与 TC93 的 COUNT 和 SUM(ATC93C) 一致
