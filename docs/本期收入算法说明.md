# 本期收入算法说明

## 最终公式

```
本期收入 = 工资总额 − 补发3 − 大病险（个人）
```

**字段对照表**：

| 中文名 | Oracle 字段 | 所在表 | 数据类型 |
|--------|------------|--------|---------|
| 工资总额 | ATC93AA | TC93 | NUMBER |
| 补发3 | ATC936 | TC93 | NUMBER |
| 大病险（个人） | ATC93BD | TC93 | NUMBER |

**运算逻辑**：

```
本期收入 = NVL(ATC93AA, 0) − NVL(ATC936, 0) − NVL(ATC93BD, 0)
```

- `NVL(x, 0)`：Oracle 函数，将 NULL 视为 0，避免空值导致计算结果为空

### 展开公式

补发3(ATC936) 经数据库交叉验证，**等于 采暖费 + 独生子女费**（202607月份405条非零记录，100%精确吻合，0条例外）。因此公式展开为：

```
本期收入 = 工资总额(ATC93AA)
         − 采暖费(ATC93W21)
         − 独生子女费(ATC93W4)
         − 大病险个人(ATC93BD)
```

本月大部分人的 ATC936 = 0（无采暖费和独生子女费），少数有这些费用的人 ATC936 > 0，公式自动按 0 处理，无需特殊分支。

## 数据来源

### TC93 — 工资发放主表

TC93 是唯一的数据来源，不需要 JOIN 或子查询即可完成本期收入计算。

**关键字段**（Oracle all_col_comments 验证）：

| 字段 | Oracle注释 | 含义 | 备注 |
|------|-----------|------|------|
| ATC930 | — | 工资记录主键 | 用于关联 TC94 扣款明细 |
| ATC931 | 工资所属年月 | 格式 YYYYMM，如 202607 | |
| ATC937 | 工资发放次数 | 同一结算单元同一月份的发放序号（01、02等） | |
| ATB930 | 结算单元流水号 | 对应 TC8M 的结算单元编号 | |
| ATC93AA | 本次工资总额 | 本次实发工资总额，含基本工资、绩效、补贴等 | |
| ATC936 | 本次免税 | 经数据库验证 = 采暖费(ATC93W21) + 独生子女费(ATC93W4)（405条非零记录100%精确吻合） | |
| ATC93BD | 大病险（个人承担） | 大病医疗互助补充保险个人缴纳部分 | |
| AAC001 | 个人编号 | 关联 AC01 人员信息表 | |
| AAC003 | 姓名 | | |
| AAC002 | 公民身份号码 | 来自 AC01 表 | |

### TC8M — 批次汇总表（用于筛选，不参与计算）

TC8M 记录每个批次的发放人数和发放月份，用于确定哪些(结算单元, 工资所属月, 批次号)组合应纳入当月报税。

| 字段 | Oracle注释 | 含义 | 备注 |
|------|-----------|------|------|
| ATB930 | 结算单元流水号 | 关联 TC93.ATB930 | |
| ATC931 | 工资所属年月 | 格式 YYYYMM | |
| ATC937 | 工资发放次数 | 同一结算单元同一月份的发放序号 | |
| ATC8G7 | 发放月份 | 实际发放/支付的月份，格式 YYYYMM | |
| ATC8M1 | 发放人数 | 该批次涉及的员工数量 | |

## 筛选条件

### 按月份筛选 TC93 记录

```sql
WHERE t93.ATC931 = :month
```

按工资所属年月筛选。

### 按 TC8M 建议批次筛选（可选）

当用户确认了特定的 TC8M 组合后，进一步筛选：

```sql
WHERE (t93.ATB930, t93.ATC931, t93.ATC937) IN (
    SELECT DISTINCT m.ATB930, m.ATC931, m.ATC937
    FROM TC8M m
    WHERE m.ATC8G7 = :pay_month
)
```

- `ATC8G7` 是实际发放月份，不等于 `ATC931`（工资所属年月）
- 例如：7月工资在8月初发放，`ATC931=202607`，`ATC8G7=202608`
- 报税日期为8月17日，故 `ATC8G7=202608` 的记录纳入7月报税
- `ATC937`（工资发放次数）区分同一结算单元同一月份的不同发放批次

## 验证公式

生成 Excel 后通过左=右校验确保数据正确性：

```
左 = 本期收入 − 养老个人 − 失业个人 − 医疗个人 − 公积金个人 − 年金(0)
右 = 实发工资 + 个人所得税 − 免税
通过 = |左 − 右| < 0.01
```

其中：

| 验证项 | Oracle注释 | 字段 | 所在表 |
|--------|-----------|------|--------|
| 养老个人 | 当月养老个人缴 | BAA001 | TC93 |
| 医疗个人 | 当月医疗个人缴 | BAA002 | TC93 |
| 失业个人 | 当月失业个人缴 | BAA003 | TC93 |
| 公积金个人 | 个人公积金月缴存额 | CAA002 | TC93 |
| 实发工资 | 本次实发金额(合计) | ATC93C | TC93 |
| 个人所得税 | 本次个人所得税 | ATC93D | TC93 |
| 免税 | 本次免税(ATC936) = 采暖费(ATC93W21) + 独生子女费(ATC93W4) | TC93 |

## 匹配率

基于202607月份数据，按(结算单元 + 工资所属月 + 当月批次)组合匹配 TC8M，精确匹配率达 **90.7%**。

剩余 9.3% 不匹配的原因：

| 原因 | 说明 |
|------|------|
| TC8M ATC931 ≠ Excel 实际月份 | TC93.ATC931 与 TC8M.ATC931 不一致（多数情况） |
| TC = 2 × Excel | 同一人同月有两条 TC93 记录，但 TC8M 只有一条 |
| 仅 ATC8G7=202608 记录 | 部分员工的 TC8M 仅有8月发放记录，7月无记录 |

这些不匹配的情况通过 **确认批次** 交互由用户手动确认处理。
