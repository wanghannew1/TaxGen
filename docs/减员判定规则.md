# 减员判定规则（增减员比对）

本文档完整记录增减员比对中"减员"（近期离职 / 待确认近期离职）的判定规则，
是业务口径与代码实现的权威说明。对应代码：`queries.py`、`templates_gen/personnel_compare.py`、`app.py`。

## 一、减员候选范围

减员候选 = **个税端在册且未标记离职**（导出文件中"离职日期"为空）的人员，
排除以下四个保护集合：

| # | 保护集合 | 数据来源 | 说明 |
|---|---|---|---|
| 1 | 发薪名单 | 所选发薪月份的 TC8M 已发放记录（ATC8M3=2） | 当月发过薪 = 仍在职 |
| 2 | 未发薪工资表 | 所选未发薪月份范围的 TC93 未发放记录 | 有未发薪工资表 = 不能减员 |
| 3 | 合同签署名单 | 合同签署时间范围内的 TC90 合同 | 新签合同 = 不能减员 |
| 4 | 最后一笔工资未发放 | 自动判定（见第二节） | 压月发薪延期规则 |

**注意**：保护集合 2（未发薪工资表）依赖用户选择的未发薪月份范围；
保护集合 4 是**自动判定**，不依赖任何月份选择。

## 二、最后一笔工资未发放保护（压月发薪延期规则）

**业务规则**：派遣员工离职后，压月发放的最后一笔工资若因故延期未发放，
则**一直不能减员**，直到该笔工资发放并报税、下个月报税时无工资才可减员。

**判定口径**（`queries.get_latest_unpaid_persons`）：
- 在"所属月 ≤ 最近发薪月（TC8M 最新 ATC8G7）"的范围内，取该人员**最新所属月**的 TC93 记录
- 该记录无对应 TC8M 已发放记录（未发放状态）→ 从减员候选**自动剔除**
- **更早的历史未发放残留不影响减员**（例：长春博众 17 人中有 16 人有 2023-2024 年、
  202510 的老未发放记录，不影响其减员）
- **未来月份**（所属月 > 最近发薪月）的工资表不参与判定（防止"最后一笔工资做到
  很多年以后"导致永久卡死）

**时序示例**（压月场景）：

| 时点 | 业务动作 | 比对结果 |
|---|---|---|
| 7/31 | 合同终止（TC90.AAA702 报减），工资结束年月 ATC90AV=202607 | — |
| 8月 | 发放最后一笔工资（发放月 202608） | 在发薪名单 → 不减员 |
| 9月初 | 报 8 月个税 | 仍不减员 |
| 10月初 | 报 9 月个税（无工资） | **正式减员** |
| 延期 | 最后一笔工资一直未发放 | 每次比对都被保护集合 4 自动剔除，不能减员 |

## 三、近期离职 vs 待确认分类

候选人员按是否命中"工资结束日期表"分类：

- **近期离职** = 候选 ∩ 工资结束日期表（有有效工资结束日期）
- **待确认近期离职** = 候选 − 近期离职（无有效工资结束日期）

工资结束日期表（`queries.get_tc90_salary_end_dates`）：
- 取**最后一份合同**（ATC90C 开始日期最大）的 `ATC90AV` 工资结束年月
- 补全为当月月末（202607 → 2026-07-31）
- 按**截止日期**（termination_deadline）过滤：工资结束日期 > 截止日期的视为未到期，
  归入待确认
- 截止日期**默认 = 最近发薪日期**（TC8M 最新 AAE036），用户可手动指定

### 3.1 延期发放人员 → 零申报（在职确认，非减员保护）

**场景**：所属月 X（如 202608）已做工资单，但 X 月无任何发放记录
（TC8M 无 `ATC8G7=X` 的已发批次），工资因到账等原因**延至 X+1 月月初（1~10日）**才发放。
TC8M 记录表现为：`ATC8G7 = X+1 月`、`AAE036`（经办时间）落在次月月初窗口、已发（`ATC8M3=2`），
关联 TC93 所属月 = X。

**判定**（`queries.get_deferred_pay_persons`）：
- 发薪月份范围（pay_months）内已做工资（TC93.ATC931 IN pay_months、ATC93G='1'）
- 且存在次月（末月+1）月初 1~10 日内的 TC8M 已发记录

**结果**：此类人员从"待确认近期离职"中**剔除**，改判**零申报**（主 sheet）——
次月已发记录证明其申报期在职、无工资结束年月也不影响，无需人工确认。
该规则**不是减员保护**（候选人仍参与减员判定；已有工资结束年月的仍按近期离职），
只是把"待确认"中的在职可确认人员**再分类**到零申报。

## 四、离职日期 = ATC90AV 工资结束年月（月末）

| 对比项 | ATC90D 合同终止日期 | ATC90AV 工资结束年月（现口径） |
|---|---|---|
| 含义 | 合同文本约定终止日 | 工资发放截止月 |
| 压月场景 | 7/31 离职但合同终止日五花八门（可晚至 2028 年） | 全部 = 202607（= 最后发薪所属月） |
| 用途 | 仅作合同信息展示 | **离职日期判定口径** |
| 格式 | DATE | NUMBER YYYYMM，补全月末 |

**异常处理**：ATC90AV 月份非法（如 202617）时**跳过**，该人员归入待确认、
离职日期留空——避免生成错误离职日期（数据修正后自动恢复正常）。

## 五、经办人过滤（优先级归属模型）

每个人员按身份类别计算**有效经办人 E**（取第一个存在的来源）：

| 身份类别 | 判定依据 | 有效经办人来源 |
|---|---|---|
| 增员-发薪 | 所选发薪月有 TC8M 已发记录 | TC8M.AAE019（所选发薪月，多批次并集） |
| 增员-发薪+未发薪 | 两者都有 | 同上（发薪优先） |
| 增员-未发薪 | 未发薪月有 TC93、无 TC8M | TC93.AAE019（未发薪月，多记录并集） |
| 增员-合同 | 期内签合同、无任何工资记录 | TC90.AAE019（最后一份合同） |
| 减员 | 无当期记录 | **最后一次发薪 TC8M → 最后一次做工资 TC93 → 最后一份合同 TC90**（链式回落） |

**匹配规则**：三个下拉（发薪经办人 TC8M / 做工资经办人 TC93 / 合同经办人 TC90）
的选中值合并为集合 S，**有效经办人 E ∈ S 即通过**（任一命中）。

**关键语义**：
- 发过薪的人员按发薪经办人归属（做工资/合同经办人对其不生效）
- 减员人员的"最后一次发薪"取发放月最大的批次（TC8M.AAE019）
- 同一来源多个经办人取并集（同月多单位发薪）
- 取经办人一律按业务口径，**不使用 MAX()**（MAX 是字典序最大，无业务含义；
  且 Oracle `ORDER BY DESC` 默认 NULL 排前，需 `NULLS LAST`）

**界面联动**：做工资经办人默认同发薪经办人、合同经办人默认同做工资经办人——
在上级下拉选择时自动选中同名（只加不减，可手动取消），显式展示回落关系。

## 六、备注 = 结算单元名称

增员/减员名单的"备注"列均填写**结算单元名称**：
- TC93.ATB931（发薪/未发薪记录）/ TC90.ATC90X（合同）
- 取不到结算单元时降级为"单位名称（非结算单元名称）：xxx"
- 名单按结算单元排序，相同单元相邻

## 七、判定伪代码

```
active       = {导出文件中 离职日期为空 的人员}
protected    = 发薪名单(所选月) ∪ 未发薪名单(所选月) ∪ 合同签署名单
unpaid_last  = 最新所属月(≤最近发薪月)记录未发放的人员   # 自动保护
candidates   = active - protected - unpaid_last

salary_end   = {证件号: ATC90AV月末}  # 最后一份合同, 月份合法, ≤截止日期
近期离职     = candidates ∩ salary_end
deferred     = 次月1~10日有TC8M已发记录的延期发放人员   # 在职确认
待确认       = candidates - 近期离职 - deferred
零申报       = active - 申报期发薪 - 近期离职 - 待确认 - 排除项   # deferred 自然落入
离职日期     = salary_end[证件号]     # 待确认人员为空

有效经办人 E:
  增员-发薪   → TC8M(所选月)
  增员-未发薪 → TC93(未发薪月)
  增员-合同   → TC90(最后一份合同)
  减员        → 最后一次发薪TC8M → 最后一次做工资TC93 → 最后一份合同TC90
过滤: E ∩ 三个下拉选中值并集 ≠ ∅
```
