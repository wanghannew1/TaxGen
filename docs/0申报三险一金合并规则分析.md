# 0申报场景下三险一金合并规则分析

> 分析日期：2026-09-08
> 数据源：Oracle TC93/TC8M/AC01 + 202512-202607 历史手工报税档 + 回盘数据

---

## 一、问题背景

手工报税时，某月工资在后续月份发放（跨月发放），该在后续月份的报送文件中如何填写三险一金（基本养老保险费/基本医疗保险费/失业保险费/住房公积金）？

**核心问题**：5月工资在6月发放时，6月报送文件中的三险一金栏应填什么？

- 选项A：合并5月+6月三险一金（翻倍填入）
- 选项B：只填6月三险一金（单倍填入）
- 取决于：5月的报送文件如何处理了三险一金

**系统实现目标**：导入历史报送数据后，自动判别应合并还是不合并。

## 三、场景分类与规则

### 场景A：5月档零申报 → 6月可合并（主要规则）

**历史实证**：长春市公共关系学校（37593），47名跨月人员。

| 人员 | 5月所属工资 | 6月所属工资 | 5月档 | 6月档 | 6月档三险一金 |
|---|---|---|---|---|---|
| 丁海峰 | 4,215 | 4,260 | 收入=0, 三险=0 | 收入=**8,475**（=4215+4260） | **翻倍**：养老702.92（=351.46×2）、医疗175.72、失业26.36、公积金504 |
| 刘一静 | 4,460 | 4,480 | 收入=0, 三险=0 | 收入=**8,940** | **翻倍**：养老702.92、医疗175.72、失业26.36、公积金610 |
| 张仪贞 | 3,800 | 3,770 | 收入=0, 三险=0 | 收入=**7,570** | **翻倍**：公积金518（=259×2） |

**规则**：5月档三险一金=0 → 6月档可合并5月三险一金（翻倍填入）。

**数据来源**：TC8M 经办年月202606，5月批次经办2026-06-04，6月批次经办2026-06-24。

### 场景B：5月档有正常三险一金 → 6月不得再合并

**规则**：5月档三险一金>0 → 6月档只填6月三险一金（单倍）。

**原理**：三险一金在累计预扣法下是**累计专项扣除**，已在5月档体现的金额会在累计值中反映，6月再填会导致多扣。

### 场景C：5月三险从6月工资借支缴纳（ATC93BE≠0）

**发现**：当5月三险一金从6月工资中"借款"缴纳时，TC93中6月所属记录会出现ATC93BE（补缴及退款保险差额·个人）≠0。

**关键验证**（202606，ATC93BE≠0的40人全部为单倍）：

| 人员 | ATC93BE | TC93三险合计 | 手工档三险 | 判定 |
|---|---|---|---|---|
| 修美茹 | -746.50 | 746.50 | 746.50 | **单倍** |
| 王莹 | +728.50 | 728.50 | 728.50 | **单倍** |
| 曲鑫 | -4629.38 | 1378.70 | 1378.70 | **单倍** |
| 边宁 | -757.50 | 757.50 | 757.50 | **单倍** |

**统计**：40人中 单倍=37，翻倍=0，零=0，未出现=2。

**规则**：ATC93BE≠0（借支缴费）→ 5月三险一金不得再加入6月（已经通过BE在收入中扣减）。

**注意**：用户假设的逻辑——"ATC93BE已把5月三险在收入中减掉"——从公式看是正确的。本期收入 = ATC93AA − ATC936 − ATC93BD − **ATC93BE** + ATC93X3 − ATC93E，BE为正时减少本期收入（相当于前期保险支出扣减），此时三险栏不应重复填入。

### 场景D：压月单位（6月工资7月发）

**实例**：吉林大学第一医院B（40797），67名跨月人员。

| 人员 | 5月所属工资 | 6月所属工资 | ATC93BE | 5月档 | 6月档 | 6月档三险 |
|---|---|---|---|---|---|---|
| 高淑坤 | 2,464.77 | 2,442.37（7月发） | -187.86 | 收入=0 | 收入=2,552.63（调整后） | 养老351.46/医疗87.86/失业13.18/公积金0（**单倍**） |
| 黄喆 | 2,230.03 | （7月发） | -187.86 | 收入=0 | 收入=2,317.89 | 同上（**单倍**） |

**规则**：6月工资7月发 → 6月档只含5月所属收入+三险（单倍），6月所属工资在7月档处理。

### 场景E：收入=0 但三险>0（0申报但正常报三险）

**发现**：202603有30人、202606有2人、202607有119人出现"收入=0 三险>0"。

| 月份 | 人数 | 典型单位 |
|---|---|---|
| 202603 | 30 | 多个单位（养351.46/医87.86/失13.18+公积金各不同） |
| 202606 | 2 | 张继萍（长春市第二中等专业学校）、张铭姗（吉林省长春铁路运输中级法院） |
| 202607 | 119 | 司法局114人（全部养351.46/医87.86/失11.25/公积金0=450.57） |

**验证**：202603的30人在202604全部有正常收入+同值三险（未翻倍）。例如吕甲利：202603收入0/险648.50 → 202604收入2600/险648.50（同值不翻倍）。

**规则**：上一月档收入=0但三险>0 → 下一月档三险不得翻倍（已在上月累计扣除中体现）。

### 场景F：司法局模式（收入=0 三险>0 且TC93无记录）

**发现**：202607回盘中119人"收入=0 三险=450.57"，但其中113人在TC93中202605-202608**完全无记录**。

**可能原因**：司法局作为政府单位，其人员可能通过手工导入方式报税，不在TC93工资系统中。

**与场景E的区别**：场景E的人员在TC93中有记录（只是当月收入=0），场景F的人员在TC93中完全无记录。

## 四、在上月报送文件中未出现（漏报）的处理

"在上月报送文件中未出现"指按证件号码在上月报送档（如 202605_正常工资薪金所得.xls）中**搜不到此人**。

这种情况有多种可能，需要区分：

| 情况 | 含义 | 处理方式 |
|---|---|---|
| **正常未出现** | 该人上月确实无应发工资（新入职、假期等） | 本月正常填本月三险，不翻倍 |
| **0申报（收入=0 三险=0）** | 上月有应发但选择了零申报（在文件中存在但收入和三险都是0） | 本月可合并上月三险（翻倍） |
| **漏报** | 上月有应发且应报三险，但填报时遗漏了此人（文件中找不到） | 本月**不得翻倍补报**，应做更正申报 |
| **跨月批次** | 该人工资所属上月但发放月在本月，上月档无此人 | 本月合并上月+本月三险（翻倍） |

### 漏报的正确处理

漏报（上月应报但未在报送文件中出现）属于**填报错误**，正确做法是：

1. **更正申报**：对上月报送文件做更正，补填此人
2. **不能在本月翻倍补报**：因为三险一金是累计扣除，上月漏报导致上月累计扣除偏少、多缴了税，但本月翻倍会导致本月扣除偏多

**关键区别**：
- **合并口径**（场景A）：上月是"零申报"——上月有意不报三险（因为工资也0），本月合并两个月的收入和三险。这是**正确的**。
- **漏报补报**：上月有收入但三险漏报，本月翻倍补填。这是**错误的**——会导致本月累计扣除多于实际应扣。

**系统判别建议**：
- IF 上月档中该人 收入=0 且 三险=0（零申报）→ 本月可合并（翻倍）
- IF 上月档中该人 收入>0 且 三险=0（漏报三险）→ 本月**不可翻倍**（应更正申报）
- IF 上月档中该人 三险>0（正常报三险）→ 本月不可翻倍（已在上月累计扣除中体现）
- IF 上月报送文件中**未找到此人** → 本月只填本月三险（无历史可合并）

## 五、系统判别逻辑建议

```
对每个跨月人员（5月所属工资在6月发放）：

IF 5月发放文件中未找到该人:
    → 6月档只填6月三险一金（单倍，无历史可合并）
ELIF 5月档中该人 收入=0 且 三险=0（零申报）:
    → 6月档合并5月+6月收入，三险一金翻倍填入
ELIF 5月档中该人 收入>0 且 三险=0（漏报三险）:
    → 6月档只填6月三险一金（单倍）+ 提示漏报需更正
ELIF 5月档中该人 三险>0（正常报三险）:
    → 6月档只填6月三险一金（单倍），5月三险已在5月档体现
END IF

额外检查：
IF TC93中该人6月所属记录 ATC93BE ≠ 0:
    → 6月档三险一金 = 单倍（5月已通过BE借支缴费）
END IF
```
