# 0申报场景下三险一金合并规则分析

> 分析日期：2026-09-08
> 数据源：Oracle TC93/TC8M/AC01 + 202512-202607 历史手工报税档 + 回盘数据

---

## 一、问题背景

手工报税时，某月工资在后续月份发放（跨月发放），该在后续月份的报送文件中如何填写三险一金（基本养老保险费/基本医疗保险费/失业保险费/住房公积金）？

**核心问题**：5月工资在6月发放时，6月报送文件中的三险一金栏应填什么？

- 选项A：合并5月+6月三险一金（翻倍填入）
- 选项B：只填6月三险一金（单倍填入）
- 取决于：5月的报送文件如何处理了三险一金

**系统实现目标**：导入历史报送数据后，自动判别应合并还是不合并。

## 三、场景分类与规则

### 场景A：5月档零申报 → 6月可合并（主要规则）

**历史实证**：长春市公共关系学校（37593），47名跨月人员。

|---|---|---|---|---|---|

| 刘一静 | 4,460 | 4,480 | 收入=0, 三险=0 | 收入=**8,940** | **翻倍**：养老702.92、医疗175.72、失业26.36、公积金610 |
| 张仪贞 | 3,800 | 3,770 | 收入=0, 三险=0 | 收入=**7,570** | **翻倍**：公积金518（=259×2） |

**规则**：5月档三险一金=0 → 6月档可合并5月三险一金（翻倍填入）。

**数据来源**：TC8M 经办年月202606，5月批次经办2026-06-04，6月批次经办2026-06-24。

### 场景B：5月档有正常三险一金 → 6月不得再合并

**规则**：5月档三险一金>0 → 6月档只填6月三险一金（单倍）。

**原理**：三险一金在累计预扣法下是**累计专项扣除**，已在5月档体现的金额会在累计值中反映，6月再填会导致多扣。

### 场景C：5月三险从6月工资借支缴纳（ATC93BE≠0）

**发现**：当5月三险一金从6月工资中"借款"缴纳时，工资所属记录会出现ATC93BE（补缴及退款保险差额·个人）≠0。

**ATC93BE 的语义**：
- 记录的是工资所属月当期的**三险调整差额**（补缴 → BE>0；退款 → BE<0）
- 它是**本期收入的减项**：`本期收入 = 工资总额(ATC93AA) − 本次免税(ATC936) − 大病险(ATC93BD) − ATC93BE + 个人交纳现金(ATC93X3) − 个人欠款(ATC93E)`
- BE>0 时本期收入减少（工资里额外扣钱补缴保险，这部分不进入三险一金栏，已在收入侧扣除）

**关键验证**（202606，ATC93BE≠0的40人全部为三险单倍）：

| 人员 | ATC93BE | TC93三险合计 | 手工档三险 | 判定 |
|---|---|---|---|---|
| 修美茹 | -746.50 | 746.50 | 746.50 | **单倍** |
| 王莹 | +728.50 | 728.50 | 728.50 | **单倍** |
| 曲鑫 | -4629.38 | 1378.70 | 1378.70 | **单倍** |
| 边宁 | -757.50 | 757.50 | 757.50 | **单倍** |

**统计**：40人中 单倍=37，翻倍=0，零=0，未出现=2。

且 141 名"5月所属 ATC93BE≠0"人员中，5月档与6月档的三险值全部相同（单倍、不翻倍）。例如长春市第二中等专业学校全员：5月档险 608/618/622 = 6月档险 608/618/622（虽 BE 有各种正值补缴 40~214元）。

**规则**：ATC93BE≠0（借支/补缴缴费）→ 5月或当月三险一金**不得翻倍**（BE<0退款或BE>0补缴，都已在收入公式中体现）。

### 场景C-2：你设想的"双月同发 + ATC93BE≥5月三险"（需逻辑推导）

**设想场景**：5月+6月工资都在6月发放，5月个人三险从6月工资借支缴纳，6月工资中 ATC93BE ≥ 5月三险。问：6月三险该翻倍包含5月，还是只报6月单倍？

**逻辑推导结论**：**应只报 6月单倍，不翻倍包含5月三险。**

理由：
- 5月三险已经通过 6月工资的 ATC93BE（补缴）**从6月收入中扣除了**
- 本期收入公式 = 工资总额 − ... − **ATC93BE**，BE 已减掉5月三险这笔借支
- 若6月三险栏再翻倍填入5月三险 → **重复扣除**（收入已扣、三险栏再填，累计专项扣除虚增）

**诚实说明**：此场景在 202606 历史数据中**实例为0**（"双月同发 + BE≠0" 人数=0），该结论基于 ATC93BE 公式语义的逻辑推导，而非历史实证。历史中末见"BE 全额=5月三险（711.5=711.5）"仅张敬垚一例。

**系统判别建议**：
- IF 该人 ATC93BE ≠ 0（借支/补缴）→ 6月档三险=单倍（不翻倍，5月三险已通过BE在收入中扣除）
- 翻倍（合并上月三险）仅在**无 ATC93BE** 且**上月零申报**时发生

**发现**：202607回盘中119人"收入=0 三险=450.57"，但其中113人在TC93中202605-202608**完全无记录**。

## 四、三组对比：确定"上月未找到"是否翻倍

用同一个月（5月工资6月发）的跨月人员，按上月档（202605）中的状态分为三组，观察本月档（202606）的三险处理：

| 上月状态 | 总人数 | 本月有三险 | 其中翻倍 | 本月三险0 | 本月未见 |
|---|---|---|---|---|---|
| **A. 上月零申报（收入0/三险0）** | 455 | 92 | **56（61%）** | 363 | 0 |
| **B. 上月有报（三险>0）** | 894 | 887 | **4（0.5%）** | 6 | 1 |
| **C. 上月未找到** | 815 | 6 | **0（0%）** | 8 | 801 |

### 结论

| 上月报送文件中的状态 | 本月三险处理 | 依据 |
|---|---|---|
| **零申报（找到且 收入=0 三险=0）** | **翻倍合并**（上月三险并入本月） | A组 61%翻倍 |
| **有报（找到且 三险>0）** | **单倍**（已在上月体现） | B组 仅0.5%翻倍 |
| **未找到（文件中没有此人）** | **单倍（不翻倍）** | **C组 0例翻倍**，且801/815本月也未出现 |

### 三个月交叉验证（换月份确认，无例外）

| 分组 | 上月未找到人数 | 本月有三险 | 翻倍数 |
|---|---|---|---|
| G1: 3月工资4月发 | 156 | 3 | **0** |
| G2: 4月工资5月发 | 692 | 2 | **0** |
| G3: 5月工资6月发 | 815 | 6 | **0** |

**三个月份合计 1,663 人"上月未找到"，本月有三险的仅 11 人，全部单倍，0 例翻倍。**

### 关键洞察

- "上月未找到"的人，绝大多数**本月也未出现**（801/815 ≈ 98%）——这些是**特殊结算单元**（如吉林银行惠农服务站 40498/40474/40472 等），可能走劳务报酬或其他处理，根本不在正常工资薪金报税流程中
- 真正需要"翻倍合并"的唯一场景是**上月零申报**（A组），不是上月未找到
- **业务规则**：不要对"上月未找到"的人翻倍补三险——他们本月也不报，翻倍反而会虚构三险数据

### 翻倍的完整触发条件（重要）

"翻倍"**并非只要上月零申报就触发**，而是必须满足：**上月的工资是本月发放的**（跨月），因此上月的收入和三险随本月工资一起并入申报。

**翻倍触发的完整链条**（5月工资在6月发）：
1. **5月有工资**（TC93有所属5月的记录）
2. **5月工资在6月发放**（跨月，ATC8G7=202606）
3. **5月档零申报**（5月工资6月才发，5月无可报收入）
4. **6月工资也在6月发放**（双月同发，ATC8G7=202606）
5. **6月档把5月+6月工资合并申报** → 收入=5月+6月，**三险一金翻倍**（=5月三险+6月三险）

**实证**（A组 6月档翻倍案例，精确吻合 收入=5月+6月、三险≈2×5月）：

| 姓名 | 5月工资 | 6月工资 | 合计 | 6月档收入 | 5月三险 | 6月档三险 |
|---|---|---|---|---|---|---|
| 杨宇函 | 4,340 | 4,340 | 8,680 | **8,680** | 750 | **1,499（≈2×750）** |
| 张国会 | 6,100 | 6,100 | 12,200 | **12,200** | 1,038 | **2,076（=2×1038）** |
| 刘赫林 | 4,220 | 4,240 | 8,460 | **8,460** | 740 | **1,481（≈2×740）** |

> 反之，若某人 5月工资在5月就已发放（非跨月）、只在5月档零申报，则6月档**不会翻倍**——因为没有"上月工资6月发"这个前因，6月档只有6月自身工资和三险。

### 系统判别建议
- IF 上月报送文件中找到 且 三险=0（零申报）→ 本月**翻倍合并**（上月三险并入本月）
- IF 上月报送文件中找到 且 三险>0 → 本月**单倍**（不重复）
- IF 上月报送文件中**未找到** → 本月**单倍**（不翻倍，历史0例翻倍；多属特殊单元本月也不报）

## 五、系统判别逻辑建议

```
对每个跨月人员（5月所属工资在6月发放）：

IF 5月发放文件中该人 三险>0（上月有报）:
    → 6月档只填6月三险一金（单倍，5月三险已在5月档体现）
ELIF 5月发放文件中该人 收入=0 且 三险=0（上月零申报）:
    → 6月档合并5月+6月收入，三险一金翻倍填入（上月三险并入本月）
ELIF 5月发放文件中未找到该人:
    → 6月档只填6月三险一金（单倍，历史0例翻倍；多属特殊单元本月也不报）
END IF

额外检查：
IF TC93中该人6月所属记录 ATC93BE ≠ 0:
    → 6月档三险一金 = 单倍（5月已通过BE借支缴费）
END IF
```
