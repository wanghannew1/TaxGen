## 二、金额字段计算关系（实证验证）

### 1. TC8M ↔ TC93 聚合（100% 精确）

```
TC8M.ATC8M2(发放总额) = Σ TC93.ATC93C(本次实发金额合计)     [396/396 全月精确匹配]
TC8M.ATC8M1(发放人数) ≈ COUNT(TC93 正常记录)                [395/396]
```

- 唯一例外：单元 37475，TC8M 人数 64 vs TC93 150 条（存在补发/多次发放重复记录）
- **TC8M.ATC8M2 对应实发金额 ATC93C，不是工资总额 ATC93AA**

### 2. TC93 内部实发金额链（96.2% 吻合）

```
ATC93C(本次实发金额合计) = ATC93Z1(实发工资) − ATC93Z2(税后扣除工会会费) − ATC93Z3(税后扣除费用) − BAA300(个人承担代理费)
```

- 19201/19958 (96.2%) 满足 `C = Z1 − Z2 − Z3`
- 剩余约 3.8% 为特殊记录（代理费 BAA300 等未从 Z1 扣除的差异）

### 3. 验证公式本质（左=右）

```
ATC93AA(工资总额) ≈ ATC93C(实发) + ATC93D(个税) + BAA200(当月个人险金合计) + 调整项
```

- 未加调整项时 15788/19958 (79.1%) 吻合——即原验证公式通过率
- 加入调整项（AG/E/Y2/BE + Z2/BAA300）后 16927/19958 (84.8%) 吻合
- 剩余 3031 条：3025 条本期收入=0（无收入扣五险），6 条特殊险种

### 4. 五险一金汇总字段

```
BAA200(当月个人险金合计) = BAA001(养老个人) + BAA002(医疗个人) + BAA003(失业个人) + CAA002(公积金个人) [+ 其他个人险]
BBA200(当月单位险金合计) = BBA001 + BBA002 + BBA003 + BBA004 + CAA001 [+ 其他单位险]
```

### 5. 免税字段关系（405条非零 100% 吻合）

```
ATC936(本次免税) = ATC93W21(采暖费) + ATC93W4(独生子女费)
```

## 三、字段体系差异（东软设计混乱点）

TC93 存在**两套工资字段体系**，2026 年实际使用情况：

| 字段 | Oracle 注释 | 2026年非零条数 | 使用情况 |
|------|------------|--------------|---------|
| ATC933 | 本次应发工资 | 8 | **基本不用** |
| ATC934 | 本次扣款 | 极少 | 基本不用 |
| ATC935 | 本次补发 | 0 | **完全不用** |
| ATC93X | 本次基本工资 | 66,253 | 部分结算单元使用 |
| ATC93AA | 本次工资总额 | 全量 | **主字段**（报税基数） |
| ATC93BF | 转款合计 | 101,652 | **主流模式**（单位转款发工资） |

**结论**：
- 报税口径统一用 `ATC93AA`（本次工资总额），不依赖 933/934/935 体系
- 多数结算单元工资通过转款（ATC93BF）发放，ATC93C 实发仍完整记录
- 不同结算单元字段使用习惯不同（如 37182 单元 933=0、X=0、BF 全覆盖），但 AA/C 始终有效

## 五、报税字段全集（按用途）

### 参与本期收入计算

```
ATC93AA(工资总额) − ATC936(本次免税) − ATC93BD(大病险个人) − ATC93BE(补缴及退款保险差额个人)
```

### 参与验证公式

```
左: BAA001(养老) BAA003(失业) BAA002(医疗) CAA002(公积金) ATC93AG(个人其他调整) ATC93E(个人欠款) ATC93Y2(扣款-大病险)
右: ATC93C(实发) ATC93Z2(税后工会会费) BAA300(个人代理费) ATC93D(个税) ATC936+ATC93BD(免税)
```
