# 工资为0不增员不报税 规则说明

> 应用模块：增减员比对
> 配置入口：特殊结算单元配置（`/special-units`）
> 更新日期：2026-09-02

---

## 一、规则概述

针对部分特殊结算单元（如吉林大学2026年短期科研助理、二院等），当人员在所选比对范围内的全部工资单**合计本期收入为 0** 时，该人员**不列入增员名单、不报个税**。

此规则与"完全排除不增员不报税"不同：
- **工资为0不增员不报税**（`zero_salary_no_add=1`）：仅当该人员本期收入合计为 0 时排除；有收入仍增员报税。
- **完全排除不增员不报税**（`exclude_all=1`）：该结算单元不论是否发工资，一律不增员不报税（从根源排除）。

## 二、判断逻辑（按人汇总）

### 2.1 三种增员原因下的排除条件

| 增员原因 | 判断范围 | 排除条件 |
|---------|---------|---------|
| **发薪** | 发薪月份范围内所有已发工资单 | 合计本期收入 = 0 → 不增员 |
| **未发薪** | 未发薪工资表所属月份范围内所有未发薪工资单 | 合计本期收入 = 0 → 不增员 |
| **发薪+未发薪** | 发薪范围 + 未发薪范围全部工资单 | 合计本期收入 = 0 → 不增员 |

### 2.2 相关工资单范围

- **发薪记录**：TC8M 已发（`ATC8M3=2`）且发放月份在用户所选发薪月份范围内。
  注意：发薪记录的**所属月份可能早于发放月份**（如发放 202608、所属 202607），必须通过 TC8M 关联确定，不能只按所属月份过滤。
- **未发薪记录**：TC93 有工资记录、但 TC8M 未发，且**所属月份**在用户所选"未发薪工资表所属月份"范围（自动扩展至当前月）内。

### 2.3 本期收入计算公式（与报税生成模块一致）

```
本期收入 = 工资总额(ATC93AA)
         − 本次免税(ATC936)
         − 大病险个人(ATC93BD)
         − 补缴及退款保险差额个人(ATC93BE)
         + 个人交纳现金(ATC93X3)
         − 个人欠款(ATC93E)
```

- 单条记录本期收入计算结果取 `max(0, ...)`（不允许负数）。
- 按人汇总：该人相关范围（发薪 ∪ 未发薪）内所有工资单的本期收入之和。
- **合计为 0 才排除**；只要任一来源有收入（>0），该人保留增员报税。

## 三、实现说明

### 3.1 关键代码

`queries.py` → `get_zero_salary_certs(conn, pay_months, unpaid_months, unit_codes)`

```
相关工资单 = 发薪记录（TC8M 已发关联，任意所属月）
          ∪ 未发薪记录（所属月 IN unpaid_months）
按人汇总本期收入（报税公式），合计==0 → 加入排除集合
```

### 3.2 配置存储

- 配置数据存储于 **SQLite**（`config_db.py` → `config.db`），**不写入 Oracle**（Oracle 只读安全规则）。
- 配置项：`zero_salary_no_add=1`（工资为0不增员不报税）。
- 维护入口：`/special-units` 页面，支持开关切换、模板导入导出。

### 3.3 配置流程

1. 进入"特殊结算单元配置"页面
2. 新增结算单元（代码可留空，按名称自动匹配）
3. 打开"工资为0不增员不报税"开关
4. 重新生成增减员比对表

## 四、已知问题与待确认

### 4.1 发薪收入0 但 未发薪收入非0 的人员（待业务确认）

实测发现：部分人员**发薪本期收入=0，但未发薪本期收入≠0**（如吉林大学2026年短期科研助理，未发薪收入 2230）。

按当前规则（方案A）：未发薪原因 → 看未发薪合计（2230≠0）→ **保留增员**（正确，需报税）。

**待确认**：业务上是否存在"发薪收入0 应排除、即使未发薪有收入"的场景？若按此（方案B）排除，将导致未发薪有收入的人员漏报。

### 4.2 历史修复记录

- **2026-09-02**：修复 `get_zero_salary_certs` 仅按单条 `ATC93AA=0` 判断 → 改为**按人汇总本期收入**（覆盖"工资总额≠0但本期收入=0"及"发薪所属月早于发放月"的情况）。
