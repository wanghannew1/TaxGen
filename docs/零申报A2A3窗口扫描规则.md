# 零申报 A2 次月发放 / A3 无批次 窗口扫描规则

> 2026-09-15 用户确认新增。解决"做了工资未发放人员不进零申报确认面板"问题。
> 关联 issue：Gitee IKFZSY / GitHub #33。本文与代码注释、操作指南同步维护。

---

## 1. 背景与问题

个税端反馈：以下 73 名人员未填写正常工资薪金所得，需进行综合所得申报（否则影响员工纳税记录与后续累计算税）。

典型场景（202608）：

| 人员 | 结算单元 | 8 月工资单（TC93） | TC8M 发放 |
|---|---|---|---|
| 高东方 | 东北师范大学（后勤保障部）1 | 202608 所属月，2825 元，已结算 | **无任何批次** |
| 佟立华 / 刘淑云 / 曲站杰 / 王辉 | 东北师范大学（后勤保障部）2 | 202608 所属月，已结算 | **无任何批次** |

这 5 人 **没有出现在零申报确认面板（本期收入为0人员）中**，导致个税端在册却无申报记录。

## 2. 根因分析

零申报候选原有三类来源（`tax_zero.build_zero_salary_suggestions`）：

| 来源 | 判定 | 这 5 人为何进不去 |
|---|---|---|
| A1 工资单收入=0 / A2 做了没发 | 只扫**已选组合内** TC93 记录 | 他们的组合（单元-202608-批1）**未被选中**：单元 8 月实际发放的是 **202607 所属月**工资单，202608 工资单在 TC8M 无批次 → 不在任何已选组合 → 扫不到 |
| B 名单在册无工资 | 须在**个税端名单**（tax_roster）在册 | 5 人不在名单快照（2026-09-11 导入）→ 进不去 |
| C 合同新入职未做工资 | 合同开始月=申报月 **且当期无工资记录** | 合同确为 8 月新签，但 2026-09-14 修复（`get_month_salary_certs`）把"当期有 TC93 工资记录"的人排除出 C 类（有工资单 ≠ 未做工资，见 Gitee IKFPJU / GitHub #26）→ 被排除 |

**三类来源全部落空 → 面板不显示。** 根子是：A 类候选只从"已选组合内记录"产生，而"做了工资但工资单不在发放清单（TC8M 无批次）"的人其组合天然不在已选组合内，成了盲区。

## 3. 新算法：A2/A3 窗口扫描

### 3.1 术语

- **组合** = (结算单元, 工资所属月, 批次)，一份工资单。
- **发放月**（TC8M.ATC8G7）= 工资实际发放的月份；**所属月**（TC93.ATC931）= 工资单归属月份。两者可不同（压月发/次月发）。
- **报税名单** = 本次已选组合内全部人员（肯定要报税的人）。
- **declare（生成零申报）** = 在正常工资薪金所得文件中生成该人员零申报行（本期收入=0、五险=0），个税端在册保留、累计计税不中断。
- **skip（不生成）** = 文件不含该人员行（原 A2 口径：无纳税义务，等发放月申报）。

### 3.2 扫描规则

1. **锚点**：用户勾选的发放月 P 已发组合（`TC8M.ATC8G7=P AND ATC8M3=2`）。
2. **窗口**：对每个锚点单元，取该单元已选组合中**最小所属月 M0**，窗口 = (M0, P]（向后搜索 TC93）。
3. **分类**（对窗口内 `ATC93G='1'` 的工资单逐条判定）：

| 条件 | 分类 | 处理 |
|---|---|---|
| TC8M 有 ATC8M3=2 批次且 ATC8G7 ≤ P | 已申报（当期/前期已发） | **跳过** |
| TC8M 有 ATC8M3=2 批次且 ATC8G7 > P | **A2 次月发放**（次月/隔月/未来已排期发放） | 进面板候选，**默认 declare** |
| TC8M 无 ATC8M3=2 批次（无批次 / 批次存在未发） | **A3 无批次**（工资单不在发放清单） | 进面板候选，**默认 declare** |

4. **人员过滤**：单上人员 − 报税名单（已选组合人员）− 个税端名单（B 类已覆盖，避免重复）− 完全排除单元。

### 3.3 窗口示例（202608 实测分布）

| 单元当期发放的所属月 | 窗口（向后搜索范围） | 单元数 |
|---|---|---|
| 202608（当月发） | 空（不扫） | 207 |
| 202607 | {202608} | 172 |
| 202606 | {202607, 202608} | 8 |
| 202605 | {202606, 202607, 202608} | 5 |

用最小所属月做下界，窗口内已发的部分工资单由"TC8M 有已发批次且 ATC8G7≤P → 跳过"天然过滤（如单元 8 月补发 202605/202606/202607 三个月，其 202606/202607 已发单不会误入）。

## 4. 与现有 A2 规则对比

| 维度 | 现有 A2（CAT_A2_UNPAID，a2_unpaid） | 新增 A2 次月发放（a2_next_month） | 新增 A3 无批次（a3_no_batch） |
|---|---|---|---|
| 扫描范围 | 已选组合内记录 | 窗口扫描（单元最小已选所属月向后） | 窗口扫描（同左） |
| TC8M 条件 | (人, 所属月) 所有批次均无 ATC8M3=2 已发匹配 | 有 ATC8M3=2 批次且 ATC8G7 > 发放月 | 无 ATC8M3=2 批次（无批次/批次未发） |
| 业务含义 | 已选批次实际未发放（防御性，UI 仅已发放，几乎不触发） | 工资单已排期未来发放（如 202609 发 202608 工资） | 工资单不在发放清单（TC8M 无记录） |
| 默认建议 | skip（无纳税义务） | **declare（8 月零申报保留在册）** | **declare（8 月零申报保留在册）** |
| 下一期处理 | 发放月按真实收入申报 | 发放月按真实收入申报（如 9 月报 202608 工资） | 发放后再按真实收入申报 |
| 验证报告标签 | `A2: 做了工资当月未发放` | `A2: 次月发放（YYYYMM发）` | `A3: 做了工资未发放，工资单不在发放清单` |

说明：
- 次月发放人员 8 月零申报与 9 月真实收入申报**不冲突**：8 月无实际收入→零申报在册保留；9 月发放→按真实收入申报，两个月各归各。
- 原 A2（a2_unpaid）逻辑保留不动，与新 A2/A3 并存。

## 7. 决策记录

- 2026-09-15：A3 定义 = 仅 TC93 有工资单、TC8M 无发放记录；A2 定义 = TC8M 有已发批次且发放月 > 当期（不限于次月）。
- 2026-09-15：窗口下界取**最小**已选所属月（已发部分由跳过规则过滤）。
- 2026-09-15：A2/A3 均**默认 declare（零申报）**——次月发放人员 8 月也要零申报（个税端在册保留），9 月再按真实收入申报。
- 2026-09-15：排除名单在册人员（B 类已覆盖），避免面板重复。
