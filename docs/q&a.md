# 个税数据逻辑 Q&A

> 探索日期: 2026-08-20
> Excel样本: `Material/202607_税款计算_工资薪金所得（8.17）.xls`

---

## Q1: TC8M是什么表？ATC8M1是什么字段？

**A**: TC8M是结算单元发放汇总表，ATC8M1是**发放人数**（不是分类）。同一组(ATB930, ATC931, ATC937)按人数拆成多行：

```
unit=37284 month=202607 seq=1  → 3行 (ATC8M1=6/14/85, 分别对应6人批、14人批、85人批)
```

---

## Q2: 为什么不能用JOIN关联TC93和TC8M？

**A**: 直接JOIN会导致TC93个人记录被"人数批次数"膨胀：
- TC93某人 gz=5370 → JOIN后匹配3行 → SUM=5370×3=16110 ❌
- 这是精确匹配率仅37.7%的根因

**正确做法**: 用IN子查询DISTINCT过滤：
```sql
WHERE (ATB930, ATC931) IN (
    SELECT DISTINCT ATB930, ATC931 FROM TC8M WHERE ATC8G7 = 202607
)
```

---

## Q3: TC8M.ATC8G7和ATC931有什么区别？

**A**: 
- **ATC931** = 工资所属月份（这笔工资属于哪个月）
- **ATC8G7** = 实际发放月份（这笔钱什么时候发的）

8月报税时，ATC8G7=202607的批次可能包含1月、2月、3月、7月的补发工资。

---

## Q4: 含ATC937的IN子查询和不含ATC937的哪个更好？

**A**: 含ATC937更好（85.5% vs 72.8%）：

| 方案 | 条件 | 精确匹配率 |
|------|------|-----------|
| A (仅unit+month) | (ATB930, ATC931) | 72.8% |
| B (unit+month+seq) | (ATB930, ATC931, ATC937) | 85.5% |

不含ATC937会把seq=2（奖金/补发）也加进来，导致金额偏高。

---

## Q5: 85.5%精确匹配后，剩余14.5%不匹配的原因是什么？

**A**: 14.5%的人**都在Excel里**（人能对上），但**金额对不上**。

典型案例：
| 姓名 | Excel | TC(方案B) | 原因 |
|------|-------|----------|------|
| 于海瑶 | 10,834.36 | 674.00 | TC8M只有seq=2，Excel取seq=1 |
| 顾婷婷 | 13,600.00 | 2,587.00 | TC8M批次与Excel不一致 |

**根因**: TC8M.ATC937有时指向seq=2（奖金/补发批次），而Excel取的是seq=1（正常工资批次）。

## Q10: 本期收入的计算公式是什么？

**A**: `本期收入 = 工资总额 - 补发3 - 大病险(个人)`

字段含义：
- **工资总额** = 应发工资（含基本工资、绩效、补贴等）
- **补发3** = 第三类补发扣款（如采暖费、独生子女费等专项扣款）
- **大病险(个人)** = 大病医疗互助补充保险个人缴纳部分

验证案例：
| 姓名 | 工资总额 | 补发3 | 大病险(个人) | Excel | 匹配 |
|------|---------|------|-------------|-------|------|
| 顾芷薇 | 8658 | 145 | 0 | 8513 | ✓ |
| 郭静明 | 3982.76 | 0 | 100 | 3882.76 | ✓ |
| 陈晨 | 12133 | 135 | 0 | 11998 | ✓ |
| 姚伟 | 7653 | 0 | 100 | 7553 | ✓ |

## Q11: 系统匹配率是多少？不匹配的原因？

**A**: 用公式 `工资总额 - 补发3 - 大病险(个人)` + IN子查询含当月批次，精确匹配率 **90.7%**（6644/7322人）。

剩余9.3%不匹配的根因：
1. **TC8M ATC931 ≠ Excel实际取用月份** — 占多数。TC8M记录的工资所属月和Excel实际报税月份不一致（如TC8M只有6月，但Excel用2月或7月）
2. **TC=2×Excel** — 136人，同一(unit,month,seq)在TC8M出现多次
3. **ATC8G7=202608的8月初发薪** — 4,734人只有202608批次无202607批次（如于海瑶）

---

## Q12: 系统应该如何设计？自动匹配还是手动确认？

**A**: **系统建议 + 用户手动确认**。

1. 系统根据TC8M批次自动推荐 (结算单元+工资所属月份+当月批次) 组合
2. 用户逐人确认推荐是否正确
3. 推荐错误时，用户可手动选择其他组合
4. 确认后系统计算本期收入

**设计原则**：系统只是建议工具，不做决定。90.7%的自动匹配率是建议基底，用户处理剩余10%。
