分区详解

  • 发放月份：下拉框选择，决定搜索哪个月发放的批次。
  • 搜索条件：结算单元名称（模糊）、所属月份（YYYYMM）、批次号、经办人，均为可选；「仅已发放」默认勾选，只显示可报送的批次。
  • 搜索结果按结算单元分组，勾选要报送的批次 → 点「添加到待报列表」。
  • 「结算单元 + 所属月份 + 批次」三元组是最小报送单位（一个"组合"）；待报列表可筛选、全选、删除。
多次搜索可累计添加。若一单元有多笔所属月工资（如 5 月与 6 月工资同在 7 月发放），应全部加入待报列表——这是跨月合并检查的前提。

同一人在待报批次中跨了多个所属月时，其三险一金需要人工确认： 多月=把多笔工资单的三险一金合并上报； 单月=只上报一个月的三险一金（按最近一次三险>0 的所属月取数； 发放月有三险 → 单月=发放月；发放月无三险（压月发）→ 取最近三险月）。 发放月有三险且单月==多月时自动跳过、不弹窗；发放月无三险时弹窗提供报/不报。

  1. 确认待报列表中勾选了本次要报送的批次（未勾选的不参与检查）。
  2. 点「检查合并规则并确认」，弹窗列出每个跨月人员：姓名、证件号、涉及结算单元、所属月、上月档案状态、系统建议、置信度、理由（含发薪模式记号）。
  3. 为每人选定「单月」「多月」或「不报」（三险按 0，仅发放月无三险时可见）： 逐个调整下拉框，或用批量按钮全部按建议（推荐）/ 全部多月 / 全部单月。
  4. （可选）勾选「记住本次选择」持久化到配置，下月同一人默认沿用（带黄色「已记住」徽标）。
  5. 点「确认并关闭」，待报列表出现绿色标记「已确认 N 人合并规则」。
系统建议仅供快速处理，最终以你在下拉框中的选择为准；标黄（置信度=中）的"多月"建议最需人工核实。

待报批次中存在本期收入为0但出现在工资单中的人员，是否生成零申报记录需要确认。

  1. 点「检查零申报并确认」，弹窗按结算单元分组卡片展示，组头含单元名称/代码、配置徽标、共 N 条/合计金额。
  2. 确认方式：整行逐个调整下拉框；三个全局批量按钮（全部按建议/全部生成/全部不生成）；每个卡片右上角也有按单元批量按钮。
  3. （可选）勾选「记住本次选择」持久化到配置。
  4. 点「确认并关闭」，出现绿色标记「已确认 N 人零申报」。
在「特殊结算单元配置」页配置过完全排除（exclude_all）的单元，人员不会出现在弹窗中，直接不生成。

  • 合并多条工资记录（默认勾选）：按人+发放月份合并（每人一行，全部合计，多月三险在此体现）或按人+所属月份合并（同人可能多行）。
  • 年平均工资总额（默认 120000 元）：用于判断解除劳动合同一次性补偿金是否达 3 倍年平均工资的交税标准。
  • 已做过合并规则/零申报确认时，选择会自动带入。
  • 点「生成报税数据」→ 等待生成（批次多时约 2-10 秒）→ 结果区显示 4 类文件：正常工资薪金所得（30 列主表）、劳务报酬所得（14 列）、全年一次性奖金收入（11 列，仅奖金>0）、人员信息采集导入模板（51 列）。
验证失败通常因应发工资=0 但实发≠0（非正常工资薪金类），可在验证报告（/api/validate/月份）中查看失败明细。

  • 入口：主页面右上角「历史申报库」。保存税务局个税端导出的历史申报文件，供合并规则判定和回盘比对使用（数据存本地 SQLite，不写 Oracle）。
  • 导入：个税端导出 Excel → 历史申报库页选择文件（可多选）→ 上传；系统按表头自动识别 4 类文件（税款计算/正常工资薪金/劳务报酬/全年一次性奖金），单文件失败不影响其他文件。
  • 合并规则判定只用税款计算类；建议导入最近 1-2 个申报期的税款计算文件即可；同人同月同类型重复导入自动覆盖。
  • 不导入也能用：合并规则全部判"上月未找到"→ 单月（保守，不虚增），但导入后零申报人员会得到"多月"建议（61% 实证），避免漏报三险。

合并规则判定（跨月人员三险一金）
上月档案状态 系统建议 置信度 理由
上月有报（三险>0） 单月 高 三险已在累计专项扣除中体现，合并上报会虚增扣除
上月零申报（收入=0 且三险=0） 多月 中 61% 历史实证合并上报，但存在例外，务必人工核实
上月未找到（档案中无此人） 单月 高 历史 0 例合并上报；多属特殊单元本月也不报
本月 ATC93BE≠0（借支/补缴） 单月 高 三险已通过借支在收入侧扣除，合并上报=重复扣除（建议不可改，属数据事实）
